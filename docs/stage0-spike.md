# Этап 0: итоги спайка

12.10.2026

Цель этапа — снять три технических риска до основной работы. Проверено на реальных
устройствах, release-сборки:

- **iPhone 16 Pro Max**, iOS 27.0.1
- **POCO F3** (Snapdragon 870), LineageOS, Android 16 (API 36)

Плюс iOS-симулятор и Android-эмулятор на этапе разработки.

| Риск | Статус |
| --- | --- |
| MapLibre + офлайн PMTiles + рельеф | **Закрыт.** Работает на обоих телефонах в авиарежиме |
| Размер пакета области | **Закрыт.** Измерен для всех 25 регионов, 62–160 МБ, резать зум не нужно |
| Передача Android-хост → iPhone | **Закрыт с оговоркой.** Работает в обе стороны; iOS изредка «принимает» сеть, но не подключается — нужен повтор, см. §3 |

Не покрыто (нет устройств): другие производители Android и версии 8–12, Android ↔ Android,
iPhone ↔ iPhone (Multipeer, в спайк не входил).

## 1. Карта

**Выбор плагина: `maplibre_gl` 0.27.1** (MapLibre Native iOS 6.28, Android 13.5). PMTiles через
`pmtiles://file://…` работает из коробки на обеих платформах, сборка iOS через Swift Package
Manager без CocoaPods. Альтернативу `maplibre` 0.3 не пробовали: она моложе, а `maplibre_gl`
закрыл все требования спайка.

Что подтверждено:

- Офлайн-стиль из `@protomaps/basemaps` 5.7 с украинскими подписями; шрифты Noto Sans и спрайты
  лежат в ассетах приложения и отдаются MapLibre через `file://` (пробелы в именах шрифтов не мешают).
- Холмистость (`hillshade`) из terrain-RGB PMTiles рендерится на обеих платформах.
- Высоты для профиля и видимости читаются в Dart напрямую из того же PMTiles (`pmtiles` + `image`),
  MapLibre для этого не нужен. Цифры на телефонах — в таблице выше.
- Точность высот из пакета против исходного Copernicus (300 случайных точек Киевской области,
  тест `spike/test/dem_reader_test.dart`): среднее 0.22 м, p95 0.68 м, максимум 1.5 м.

Ограничения и наблюдения:

- **3D-рельефа (terrain) в MapLibre Native нет**, только hillshade. Для топокарты этого
  достаточно; горизонтали можно добавить позже векторным слоем из того же DEM.
- Диагональные полосы в Android-эмуляторе — артефакт его GPU, на POCO F3 их нет.
- Пакеты на Android можно класть в `Android/data/<id>/files` (USB/adb без root), на iOS —
  в Documents через Finder. Это пригодится и для ручной загрузки пакетов в основном приложении.

Площадь приморских регионов включает территориальные воды (полигоны OSM), поэтому
Одесская и Крым больше официальных цифр; морские тайлы почти ничего не весят.

Декодирование тайла в Dart: WebP ~3.5 мс, PNG ~1.6 мс. С кэшем тайлов на профиль это
не влияет, но если тепловая карта высот упрется в декодирование, PNG — запасной вариант.

**Решение:** карта до z15, высоты до z12 в WebP с шагом 1 м. Самый большой пакет (Киевская,
карта + высоты) — около 160 МБ. Резать зум или делить области не нужно, до лимита GitHub
Releases (2 ГБ на файл) далеко. Вся Украина — около 2.7 ГБ.

## 3. Передача по Wi-Fi

Реализовано в спайке:

- **Android-хост:** `WifiManager.startLocalOnlyHotspot`, SSID и пароль генерирует система.
  Разрешения: `NEARBY_WIFI_DEVICES` на 13+, геолокация на 8–12 (запрос нативный, без
  `permission_handler`: свежие версии требуют compileSdk 37).
- **iPhone-клиент:** `NEHotspotConfiguration`; entitlements Hotspot Configuration и Access
  WiFi Information, `NSLocalNetworkUsageDescription`.
- **Android-клиент:** `WifiNetworkSpecifier` + `bindProcessToNetwork` (10+), `WifiManager.addNetwork` (8–9).
- **QR-приглашение** (~170 байт JSON): SSID, пароль, тип безопасности, IPv4-адреса точки,
  порт, ключ 256 бит, направление. Клиент параллельно пробует все адреса.
- **Канал:** TCP, кадры AES-256-GCM, нонс не передается (направление + счетчик), поэтому
  повтор, перестановка или отражение кадра не проходят проверку. Клиент первым доказывает знание
  ключа, до этого хост ничего не отправляет. Шифрование через CryptoKit / javax.crypto
  (`cryptography_flutter`).

Проверено на телефонах (POCO F3 — хост, iPhone — клиент), 12 передач:

| Сценарий | Результат |
| --- | --- |
| Android → iPhone, 10/20/50/100 МБ | ✅ sha256 совпал, 3.4–10.5 МБ/с |
| iPhone → Android, 20 МБ | ✅ 5.2–11.9 МБ/с |
| QR с экрана POCO, сканер на iPhone (`mobile_scanner`) | ✅ распознается мгновенно |
| От нажатия «Подключиться» до TCP | ~3.5 с (DHCP; первая TCP-попытка всегда теряется) |
| iOS «принял» сеть, но не подключился | ❗ 2 случая из 12, ни одного кадра на точке доступа |

Находки:

- **Тихий отказ iOS.** `NEHotspotConfigurationManager.apply` возвращает успех, а iPhone даже не
  пытается подключиться (по логу hostapd — ни одного кадра). Повторное применение помогает.
  С `joinOnce = true` iOS не сообщает текущую сеть, и отказ не обнаружить; поэтому
  **`joinOnce = false`**, проверка через `NEHotspotNetwork.fetchCurrent` (entitlement Access
  WiFi Information) и автоповтор через 6 с, конфигурация удаляется после передачи. Автоповтор
  реализован, но в контрольной серии сбой не повторился, так что в деле он не проверен. Запасной
  путь в UI: показать SSID и пароль для ручного подключения.
- **Адрес точки.** Android 16 выдает LocalOnlyHotspot случайную подсеть (10.85.97.0/24 на
  `wlan2`), а телефон параллельно остается в домашнем Wi-Fi. Если в QR попадает домашний адрес,
  передача молча идет через роутер — так один прогон оказался ложным. Теперь хост кладет в QR
  только адреса интерфейса, появившегося после запуска точки.
- **Скорость.** Точка поднимается на 2.4 ГГц, канал 1, 20 МГц (выбор диапазона для
  LocalOnlyHotspot — системный API), отсюда 3–12 МБ/с. Для слоев (килобайты–мегабайты)
  это с запасом.
- **Безопасность точки:** WPA3-SAE transition; iPhone подключается по SAE.
- LocalOnlyHotspot в эмуляторе падает с `ERROR_GENERIC` — только железо.
- Юнит-тесты: передача, отказ при чужом ключе, QR. Эмулятор ↔ симулятор: одна передача через
  `adb forward` оборвалась и не воспроизвелась, на железе обрывов не было ни разу.

**Для основного приложения:** joinOnce=false + проверка + повтор + ручной запасной путь;
только адреса точки в QR; таймауты и докачка на уровне протокола.

- Лицензия спрайтов `protomaps/basemaps-assets` не указана в репозитории — уточнить до релиза
  или нарисовать свои иконки.
- `mobile_scanner` тянет ML Kit (уже в спеке, блокирует F-Droid).
- Подпись: команда разработчика 4JPBK84G96 прописана в проекте спайка; для основного
  приложения нужен отдельный App ID `com.synckord.horyzontal` с теми же capabilities.

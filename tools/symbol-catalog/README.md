# Каталог знаков APP-6D для `horyzontal_symbols`

`generate.py` собирает `packages/horyzontal_symbols/lib/src/catalog/data.g.dart`: наборы
знаков, сущности (entity / entity type / entity subtype), модификаторы секторов 1 и 2,
стандартные принадлежности, статусы, HQ/TF/dummy и амплификаторы эшелона и подвижности
номерного SIDC APP-6D / MIL-STD-2525D с английскими и украинскими названиями. Данные лежат
в git, в рантайме сеть не нужна, CI скрипт не запускает.

| Файл | Что это |
| --- | --- |
| `generate.py` | генератор, только стандартная библиотека Python |
| `uk.json` | украинские названия: ключ → `[English, українською]`, плюс `aliases` для поиска |
| `review-uk.md` | названия, которые должен проверить носитель языка из войск |

Источник — Esri [joint-military-symbology-xml](https://github.com/Esri/joint-military-symbology-xml)
(Apache-2.0), коммит `094e7647f0bdd001e42fd2a73ba802c995af20aa` от 2024-09-19, файлы
`instance/*.xml`. Атрибуция и текст лицензии — `packages/horyzontal_symbols/LICENSE-jmsml`.

## Запуск

```bash
git clone https://github.com/Esri/joint-military-symbology-xml.git /tmp/jmsml
git -C /tmp/jmsml checkout 094e7647f0bdd001e42fd2a73ba802c995af20aa
```

```bash
python3 -I tools/symbol-catalog/generate.py /tmp/jmsml packages/horyzontal_symbols/lib/src/catalog
dart format --line-length 100 packages/horyzontal_symbols/lib/src/catalog/data.g.dart
```

Форматирование — обязательный шаг после генерации: генератор пишет код без переносов.
Проверка:

```bash
cd packages/horyzontal_symbols && dart analyze && dart test test/catalog_test.dart
```

Генератор падает, если в `uk.json` нет ключа из источника, есть ключ, которого в источнике
больше нет, или английский текст рядом с переводом не совпадает с источником. Так при
обновлении JMSML переименованная запись не сохранит старый перевод молча. Список расхождений
без записи файла:

```bash
python3 -I tools/symbol-catalog/generate.py /tmp/jmsml --missing
```

## Ключи `uk.json`

| Ключ | Что |
| --- | --- |
| `set:10` | название набора |
| `10:121100` | сущность: набор и шесть цифр позиций 11-16 |
| `10:m1:41`, `10:m2:01` | модификатор сектора 1 или 2 |
| `10:xxxx95` | специальный подтип (позиции 15-16 при любом типе, у наземных подразделений 95-98) |
| `context:1`, `identity:3`, `status:0`, `hqtfd:2` | однозначные поля SIDC |
| `ampgroup:1`, `amp:16` | группа амплификатора (позиция 9) и амплификатор (позиции 9-10) |

Переводы привязаны к коду, а не к английскому слову: одно и то же слово в разных наборах
значит разное ("Light", "Space", "Missile"), а прилагательные согласуются с родителем
("Легкий міномет", но "Легка гаубиця"). Подтип можно называть коротко, если в списке он
показывается под родителем ("Коло" под "Район вільного вогню"); полный путь дают
`SymbolCatalog.path` и `describe`. Апостроф в названиях — `’`; поиск считает `’`, `'` и `ʼ`
одним символом. `aliases` — дополнительные слова для поиска (аббревиатуры вроде "КП", "БМП",
разговорные "дрон"), в интерфейсе не показываются.

Строки, в которых нет уверенности, перечислены в `review-uk.md`. После правки `uk.json` строку
оттуда нужно убрать и перегенерировать данные.

## Что не вошло

- Наборы METOC (45 атмосфера, 46 океанография, 47 космическая погода), 00 и 98: в задачу
  символьного конструктора не входят. Добавить — строка в `SETS` и переводы.
- 27 "Dismounted individual" и прочие изменения 2525E / APP-6E: в JMSML их нет, JMSML описывает
  только версию `10` (2525D / APP-6D). `Sidc` принимает любые две цифры версии, но таблицы
  есть только для `10`.
- Позиции 21-30 тридцатизначного SIDC JMSML не описывает; `Sidc` хранит их как есть, `describe`
  выводит без расшифровки.
- Совместимость модификаторов и амплификаторов с конкретными сущностями (`LimitUseTo`,
  `CompatibleSymbolSetIDs`) и графика знаков в каталог не переносятся.

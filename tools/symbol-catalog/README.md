# Каталог знаків APP-6D для `horyzontal_symbols`

`generate.py` збирає `packages/horyzontal_symbols/lib/src/catalog/data.g.dart`: набори
знаків, сутності (entity / entity type / entity subtype), модифікатори секторів 1 і 2,
стандартні належності, статуси, HQ/TF/dummy та ампліфікатори ешелону й рухомості
числового SIDC APP-6D / MIL-STD-2525D з англійськими й українськими назвами. Дані лежать
у git, під час роботи мережа не потрібна, CI скрипт не запускає.

| Файл | Що це |
| --- | --- |
| `generate.py` | генератор, лише стандартна бібліотека Python |
| `uk.json` | українські назви: ключ → `[English, українською]`, плюс `aliases` для пошуку |
| `review-uk.md` | назви, які має перевірити носій мови з війська |

Джерело — Esri [joint-military-symbology-xml](https://github.com/Esri/joint-military-symbology-xml)
(Apache-2.0), коміт `094e7647f0bdd001e42fd2a73ba802c995af20aa` від 2024-09-19, файли
`instance/*.xml`. Атрибуція й текст ліцензії — `packages/horyzontal_symbols/LICENSE-jmsml`.

## Запуск

```bash
git clone https://github.com/Esri/joint-military-symbology-xml.git /tmp/jmsml
git -C /tmp/jmsml checkout 094e7647f0bdd001e42fd2a73ba802c995af20aa
```

```bash
python3 -I tools/symbol-catalog/generate.py /tmp/jmsml packages/horyzontal_symbols/lib/src/catalog
dart format --line-length 100 packages/horyzontal_symbols/lib/src/catalog/data.g.dart
```

Форматування — обов'язковий крок після генерування: генератор пише код без переносів.
Перевірка:

```bash
cd packages/horyzontal_symbols && dart analyze && dart test test/catalog_test.dart
```

Генератор падає, якщо в `uk.json` немає ключа з джерела, є ключ, якого в джерелі
вже немає, або англійський текст поруч із перекладом не збігається з джерелом. Так під час
оновлення JMSML перейменований запис не збереже старий переклад мовчки. Список розбіжностей
без запису файлу:

```bash
python3 -I tools/symbol-catalog/generate.py /tmp/jmsml --missing
```

## Ключі `uk.json`

| Ключ | Що |
| --- | --- |
| `set:10` | назва набору |
| `10:121100` | сутність: набір і шість цифр позицій 11-16 |
| `10:m1:41`, `10:m2:01` | модифікатор сектора 1 або 2 |
| `10:xxxx95` | спеціальний підтип (позиції 15-16 за будь-якого типу, у наземних підрозділів 95-98) |
| `context:1`, `identity:3`, `status:0`, `hqtfd:2` | однозначні поля SIDC |
| `ampgroup:1`, `amp:16` | група ампліфікатора (позиція 9) і ампліфікатор (позиції 9-10) |

Переклади прив'язано до коду, а не до англійського слова: одне й те саме слово в різних наборах
означає різне ("Light", "Space", "Missile"), а прикметники узгоджуються з батьківським записом
("Легкий міномет", але "Легка гаубиця"). Підтип можна називати коротко, якщо в списку він
показується під батьківським ("Коло" під "Район вільного вогню"); повний шлях дають
`SymbolCatalog.path` і `describe`. Апостроф у назвах — `’`; пошук вважає `’`, `'` і `ʼ`
одним символом. `aliases` — додаткові слова для пошуку (абревіатури на кшталт "КП", "БМП",
розмовні "дрон"), в інтерфейсі не показуються.

Рядки, у яких немає певності, перелічено в `review-uk.md`. Після правки `uk.json` рядок
звідти потрібно прибрати й перегенерувати дані.

## Що не ввійшло

- Набори METOC (45 атмосфера, 46 океанографія, 47 космічна погода), 00 і 98: до завдання
  конструктора знаків не входять. Додати — рядок у `SETS` і переклади.
- 27 "Dismounted individual" та інші зміни 2525E / APP-6E: у JMSML їх немає, JMSML описує
  лише версію `10` (2525D / APP-6D). `Sidc` приймає будь-які дві цифри версії, але таблиці
  є лише для `10`.
- Позицій 21-30 тридцятизначного SIDC JMSML не описує; `Sidc` зберігає їх як є, `describe`
  виводить без розшифрування.
- Сумісність модифікаторів і ампліфікаторів з конкретними сутностями (`LimitUseTo`,
  `CompatibleSymbolSetIDs`) і графіка знаків у каталог не переносяться.
